# 지원용 프로젝트 설명: AI 체력 코치

## 해결하려던 문제

국민체력100 측정값을 받은 뒤 어떤 운동을 해야 하는지까지 이어지는 흐름이 부족했다. 측정 결과, 또래 비교, 공식 운동 영상과 근거 기반 코칭을 연결하는 서비스를 팀으로 만들었다. 센터 측정과 HOME 측정의 정확도가 다르므로 같은 확정 등급처럼 보여주지 않는 것이 중요했다.

## 내 기여와 팀의 기여

내 주 담당은 Backend·DB였다. 백엔드 API, 사용자 측정 기록, 백분위 조회, 사용자·프로필별 세션 격리, 로컬 실행 패키지와 프론트·RAG 연결을 맡았다. 생애주기에 맞지 않는 영상이 섞이는 문제와 로그인·프로필 전환 뒤 이전 기록이 남는 문제를 실제 API와 화면 흐름에서 확인했다.

RAG 데이터 구축과 모델 서버·검색 평가, 프론트 UI, 기획·골드셋 검수·GCP 배포는 팀 역할과 함께 설명한다. 모든 성과를 개인 성과로 옮기지 않는다. [팀 역할 근거](TEAM_ROLES.md)와 [개인 백엔드 작업 기록](../apps/api/KIMMIN_BACKEND_WORKLOG.md)을 연결했다. 과거 날짜별 구현량을 확인할 기록이 없는 구간은 작업 기록의 한계를 유지한다.

## 접근 방법

연령·성별·측정 출처를 구조화된 API 계약으로 전달하고, HOME 결과는 측정 오차를 고려한 구간으로 표시했다. 운동명과 영상은 실제 데이터에서 고르고 모델은 그 범위의 설명을 맡도록 연결했다. 사용자 DB와 대화 세션을 분리하고, 생애주기는 추천 가산점 대신 후보 필터에 반영했다.

## AI 활용과 검증

제품에서는 Qwen3-4B Q4, 임베딩 모델과 Chroma 검색을 사용한다. 개발 과정에서는 Codex를 활용한 구현·문제 해결 기록이 남아 있다. 이번 문서 정리 역시 Codex로 작성했다(ai-assisted). 코드 생성 비율이나 전체 수동 수정량을 측정한 기록은 없다.

AI 응답은 API·프론트 계약, 검색 경로, 근거 제한, 프로필 분리와 블라인드 검토로 각각 검증했다. 검색 경로를 통과했다는 사실과 답변이 모든 상황에서 정확하다는 주장은 구분한다.

## 결과와 한계

| 기존 문서에 기록된 평가 | 결과 | 이번 작업의 확인 범위 |
|---|---|---|
| 공식 평가셋 HTTP·경로 | 145/145 | 기존 평가 문서 확인. 이번에 실서버 145건 재수집하지 않음 |
| 근거 제한·검색 분기 | R5 80/80, R8 65/65 | 해당 평가 조건의 기록이며 신규 일반화 점수로 주장하지 않음 |
| 사용자 분리 | R11 6/6 | 기존 계약 평가의 결과 |
| 3인 블라인드 검토 | 12/12 다수결, 10건 만장일치 | 12건의 정성 검토이며 전체 사용자 평가가 아님 |

[상세 평가와 시행착오](PORTFOLIO.md), [재현 절차와 필요한 자산](../evaluation/README.md)에 평가 진입점과 실행 조건이 있다. 공개본에는 공식 골드셋·응답 원본·개인 기록·모델·Chroma가 포함되지 않아 clone만으로 145건을 재현할 수 없다. 이 제약을 지우고 같은 점수를 새 평가처럼 표기하지 않았다. 공개 응답 품질의 독립 검증을 확대하는 일이 후속 과제다.

## 공개 범위

이번 변경에는 사용자 DB, 계정 정보, 실제 대화, 비공개 골드셋·원본 응답을 포함하지 않는다. 팀원 역할은 기존 공개된 역할 문서를 기준으로 유지했다.
